# How development works

This page explains how the development setup fits together, beyond the day-to-day
loop on the [index](000-index.md).

## The moving parts

`make dev` uses dekit to run three tasks at once. dekit is a process runner, and it
reads the task list from `dekit.yaml`.

- Elm: `node dev-server.mjs hot` runs elm-watch. It compiles `src/Main.elm`, serves
  the client on port 8000, reloads the browser on each change, and forwards every
  `/api/` request to the server on port 3000.
- Tailwind: `tailwindcss --watch` rebuilds `client/target/app.css` on each change.
- Server: `cargo watch` reruns two steps on each Rust change. First it regenerates
  `client/src/Api/Types.elm` with the `genelm` command. Then it runs
  `cargo run -- serve`, which listens on port 3000.

So in development you open port 8000. elm-watch serves the client and forwards the
API calls and the websocket to the server on port 3000.

## Shared types

The server is the source of truth for the API types. The dev server regenerates
`client/src/Api/Types.elm` whenever the Rust types change, so a mismatch becomes an
Elm type error. You can also regenerate the file with `make genelm`. Do not edit it
by hand.

## Database

The server uses sqlx for database access. The `sqlx::query!` macros test each query
against a live database when the server compiles, so the database must run and hold
the current schema before the server builds. Apply the migrations with sqlx-cli to
create that schema:

```sh
cd server && sqlx migrate run
```

The compiled server also applies pending migrations at startup. So you run
`sqlx migrate run` by hand before a build that adds a migration, and the server
keeps the database current on each run after that.

## Directory layout

- `server/`: the Rust server.
- `client/`: the Elm client, with `app.css` and `index.html`.
- `client/src/Api/Types.elm`: the generated API types. Do not edit this file.
- `docs/`: this documentation.
- `Makefile` and `dekit.yaml`: the build steps and the dev-runner task list.

## Git hooks

Point Git at the repository hooks once:

```sh
git config core.hooksPath .githooks
```

The pre-commit hook runs `elm-format --validate` on the client and `cargo fmt
--check` on the server. If either command reports a problem, run `make format`,
stage the changes, and commit again.
